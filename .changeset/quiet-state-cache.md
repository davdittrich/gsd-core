**An untracked `.planning/state.json` is now git-ignored, so `/gsd-ship` no longer refuses on it** — the derived cache was rewritten at every boundary command but never committed or ignored, leaving the tree dirty after a workflow's final commit. Each clone's `.git/info/exclude` now lists it (skipped when `commit_docs` is false); a copy committed earlier stays tracked and modified, and `/gsd-health` now reports it as warning `W031` with the exact, idempotent `git rm --cached --ignore-unmatch` to run once (GSD never untracks it for you). Limit: W031 is advisory only, so a tracked copy keeps being rewritten, and the tree stays dirty, until you run that command. Git probes about the project (`commit_docs` ignore check, the planning snapshot, the exclude edit) now ask the repository found from the project directory and ignore an exported `GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE`/`GIT_COMMON_DIR`; this changes `commit_docs` for every `loadConfig` caller only in a setup whose sole repository discovery is such an exported variable (e.g. a bare-repo dotfiles layout), which is unsupported. (#5505)
